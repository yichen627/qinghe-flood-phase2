# 青河流域洪水预报系统需求规格说明书

作者：陈一，河海大学计算机与软件学院软件工程专业24级1班，2406050103。个人完成。

## 1 范围与状态

以一期三水源新安江引擎为核心，最终覆盖UC1–UC5。本次交付只完成阶段1需求契约和阶段2预报链路，不能称为二期全部完成。无专门Web工作台。使用FastAPI的交互式API文档操作。

数据是课程虚拟流域，F=2000km²、Δt=6h、U严格为92.6。采用学生包v2汇流，沿用冻结参数，不重新率定event4。event4在一期已检验，二期仅用于固定基线回归，不能再称为全新盲测。

## 3 功能要求

- FR-M1：接收UTF-8 CSV及该场state0；保存原文、SHA256、规范化逐时段记录与逐行质控问题；去重而不覆盖原数据。
- FR-QC：检查缺列、空表、空值、-999、非数、NaN/Inf、负雨量/EM/Q、时间重复/乱序/非6h间隔，标记ERROR；六站泰森复算与面雨量差异超过外置阈值标记WARNING。
- FR-QC-OBS：允许无Q实测的未来预报输入；缺失或非法Q只告警，该时段不参与指标；P/EM/六站缺测禁止计算，不自动插补。
- FR-M2：POST创建持久化QUEUED任务，独立单worker领取，HTTP调用独立模型容器，转为RUNNING、SUCCEEDED或FAILED；请求中不包含用于率定的观测Q。
- FR-M3：分页查询事件/任务、逐时段Q及指标、蓝色实测橙色模拟PNG。图只对SUCCEEDED任务可用。失败返回409，模型超时等原因保存在任务中。
- FR-M5-PART：任务创建时冻结输入、初态、完整参数与模型版本摘要；本次仅提供不可变快照，不宣称完成全部操作审计。

## 4 非功能要求

- NFR-ARCH：接口层→应用服务层→仓储/模型HTTP适配器；模型纯函数不依赖数据库或API。模型服务独立部署。
- NFR-UNIT：保留一期每步守恒断言；拒绝初态超容，不允许静默丢水；不使用python -O。
- NFR-REPRO：黄金CSV、逐场初态、冻结参数、一期基线输出纳入Git；校验全40时段Q一致，event4 DC≥0.85。
- NFR-DATA：SQLite外键、WAL、事务；参数绑定SQL；任务以短事务原子领取，HTTP运行时不占数据库事务。
- NFR-OPS：Compose启动API、模型、单worker；持久化命名卷；健康检查；配置和密钥来自JSON/环境变量。
- NFR-LIMIT：本轮仅单机单worker；API单进程；没有正式身份权限、产品签发和外部群通知。演示密钥只适合localhost。
- NFR-CONTRACT：提交OpenAPI JSON，由实际路由生成，测试核对与运行时一致。

## 5 后续状态设计

任务状态：QUEUED→RUNNING→SUCCEEDED/FAILED。worker崩溃后的RUNNING任务在租约过期后转FAILED，保留记录，不静默覆盖；用户可新建任务重算。

产品后续状态：DRAFT→REVIEWED→SIGNED→PUBLISHED；只读关联成功任务快照。签发和发布必须显式授权，自动预报不能自动签发。产品、参数集、方案、audit_log、qc_alert和notification_outbox实体预留在设计中，当前不创建空表冒充功能。
