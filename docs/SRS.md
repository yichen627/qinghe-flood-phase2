# 青河流域洪水预报系统需求规格说明书

作者：陈一，河海大学计算机与软件学院软件工程专业24级1班，2406050103。个人完成。

## 1 范围与状态

以一期三水源新安江引擎为核心，版本1.1.0覆盖UC1–UC5的本地教学流程，交付部署配置、自动化测试、验收证据、运行维护手册及个人总结报告。已提供本地预报工作台，覆盖输入、起报、曲线、签发和治理操作；通知以本地值班收件箱演示，不对接外部群聊。

数据是课程虚拟流域，F=2000km²、Δt=6h、U严格为92.6。采用学生包v2汇流，沿用冻结参数，不重新率定event4。event4在一期已检验，二期仅用于固定基线回归，不能再称为全新盲测。

## 3 功能要求

- FR-M1：接收UTF-8 CSV及该场state0；保存原文、SHA256、规范化逐时段记录与逐行质控问题；去重而不覆盖原数据。
- FR-QC：检查缺列、空表、空值、-999、非数、NaN/Inf、负雨量/EM/Q、时间重复/乱序/非6h间隔，标记ERROR；六站泰森复算与面雨量差异超过外置阈值标记WARNING。
- FR-QC-OBS：允许无Q实测的未来预报输入；缺失或非法Q只告警，该时段不参与指标；P/EM/六站缺测禁止计算，不自动插补。
- FR-M2：POST创建持久化QUEUED任务，独立单worker领取，HTTP调用独立模型容器，转为RUNNING、SUCCEEDED或FAILED；请求中不包含用于率定的观测Q。
- FR-M3：分页查询事件/任务、逐时段Q及指标、蓝色实测橙色模拟PNG。图只对SUCCEEDED任务可用。失败返回409，模型超时等原因保存在任务中。
- FR-M5：任务创建时冻结输入、初态、参数与模型版本，SQL触发器保护快照；创建、执行、失败、切换、回放、签发及通知均有只追加审计。schema1旧记录保留快照，不补造历史操作。
- FR-PRODUCT：DRAFT→REVIEWED→SIGNED→PUBLISHED，不允许越级；预报员创建草稿，值班长复核签发发布，管理员不能冒充值班长。签发产品可导出JSON，只有PUBLISHED可匿名访问。
- FR-VERSION：参数新增版本而非覆盖，方案绑定版本；活动、灰度、待回滚或启用计划引用的方案不可归档。灰度按事件指纹稳定分桶；显式选择方案不参与分桶。
- FR-SCHEDULE：计划存SQLite，重启可恢复；创建任务、记录触发和推进下一时刻在同一事务完成。暂停错过的多周期合并为一次，不产生补报风暴。
- FR-NOTIFY：产品发布、质控异常、预报失败和调度失败写事务出站队列，本地投递幂等；失败退避、到上限进死信，管理员可重试死信。

## 4 非功能要求

- NFR-ARCH：接口层→应用服务层→仓储/模型HTTP适配器；模型纯函数不依赖数据库或API。模型服务独立部署。
- NFR-UNIT：保留一期每步守恒断言；拒绝初态超容，不允许静默丢水；不使用python -O。
- NFR-REPRO：黄金CSV、逐场初态、冻结参数、一期基线输出纳入Git；校验全40时段Q一致，event4 DC≥0.85。
- NFR-DATA：SQLite外键、WAL、事务；参数绑定SQL；任务以短事务原子领取，HTTP运行时不占数据库事务。
- NFR-OPS：Compose启动API、模型、单worker和单scheduler；持久化命名卷；健康检查；配置和密钥来自JSON/环境变量；依赖和基础镜像摘要固定。
- NFR-LIMIT：单机单worker和单scheduler，API单进程，三类演示角色密钥只适合localhost，不代替正式多用户登录。模型注册表是元信息，不是自动镜像部署平台。业务签发记录不是密码学数字签名。
- NFR-CONTRACT：提交OpenAPI JSON，由实际路由生成，测试核对与运行时一致。

## 5 状态设计与异常处理

任务状态：QUEUED→RUNNING→SUCCEEDED/FAILED。worker崩溃后的RUNNING任务在租约过期后转FAILED，保留记录，不静默覆盖；用户可新建任务重算。

产品状态：DRAFT→REVIEWED→SIGNED→PUBLISHED，内容不可变且与成功预报关联。定时起报不自动创建、签发或发布产品。通知状态PENDING→DELIVERED/FAILED；FAILED可显式重试，DELIVERED不可重复投递。新增实体和事务约束见DATABASE.md。
